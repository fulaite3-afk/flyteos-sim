## 二、技术可行性分析

### 2.1 与SITL闭环的对接

当前SITL已实现HTTP API遥测推送：

```
C++ SITL → /api/telemetry (JSON) → CesiumJS前端
CesiumJS → /api/rc (POST) → C++ SITL
```

**对接方案**：CesiumJS前端直接消费SITL的`/api/telemetry` JSON数据，用`SampledPositionProperty`驱动飞行器实体移动，无需改动后端C++代码。

### 2.2 Three.js → CesiumJS 功能映射

| Three.js 当前功能 | CesiumJS 对应 | 难度 |
|------------------|---------------|------|
| Perlin噪声地形 | Cesium World Terrain (30m DEM) | 低：直接替换 |
| 简易云层(flat plane) | 场景雾效+大气散射 | 低：内置支持 |
| 飞行器(cylinder) | Entity + GLB模型 | 中：需建模 |
| 键盘控制 | 同上，改用Cartographic坐标 | 低 |
| HUD叠加 | HTML overlay (不变) | 无 |
| Raycaster高度查询 | `sampleTerrainMostDetailed()` | 低：API更简洁 |
| 程序化地面 | Quantized-Mesh地形 | 低：自动 |

### 2.3 坐标系

| | Three.js | CesiumJS |
|--|---------|----------|
| 坐标系 | 笛卡尔(x,y,z) | WGS84(lon,lat,alt) |
| 上方向 | Y轴 | 椭球法线 |
| 距离 | 米 | 弧度/米混合 |
| 地形查询 | Raycaster | `sampleTerrain()` |

**转换**：SITL输出的NED坐标需转为WGS84，已有转换公式。

## 四、风险评估

| # | 风险 | 概率 | 影响 | 缓解措施 |
|---|------|------|------|---------|
| 1 | Cesium Ion Token免费额度不足 | 低 | 中 | 预缓存+本地代理，50K/月够单人开发 |
| 2 | 离线环境无法加载地形 | 中 | 高 | 自动降级到Perlin噪声（已设计） |
| 3 | 首次加载慢(4MB JS+地形) | 中 | 低 | lazy loading+预缓存模拟区域 |
| 4 | GLB浮空器模型缺失 | 高 | 低 | 先用Cesium内置实体(Cylinder/Sphere) |
| 5 | 大量航点时性能下降 | 低 | 低 | CesiumJS自带LOD和视锥裁剪 |

**最大风险**：离线兼容。缓解方案已设计（降级到程序化地形）。

## 五、性能基准方案

### 5.1 测试环境
- Chrome 120+, GPU: 集成显卡
- 模拟区域：10km×10km
- 飞行高度：0~500m AGL

### 5.2 测试指标

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| 首屏时间 | <5s | Performance API |
| FPS(飞行中) | ≥30 | `requestAnimationFrame` 计数 |
| FPS(悬停) | ≥45 | 同上 |
| 内存 | <500MB | Chrome DevTools |
| 地形请求 | <50/min | Network面板 |

### 5.3 优化预案

1. 地形瓦片本地代理缓存
2. 模拟区域预加载
3. 超出视野实体自动释放
4. `requestRenderMode` 降低空闲帧率
